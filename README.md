# EV 인센티브 자격확인/매칭 앱

캘리포니아 EV 인센티브 프로그램(RYR, Clean Cars 4 All, DCAP, MyFirstEV, CALeVIP,
유틸리티 충전기 리베이트)에 대한 고객 자격을 확인하고, 어떤 프로그램에 신청할 수
있는지 매칭해주는 도구입니다. 신청 이후 케이스 상태를 이력과 함께 관리합니다.

## 현재 상태

무료 자격확인 리드 수집, 결제 후 정식 신청, 프로그램 매칭, 케이스 이력 관리 및 운영자 관리자 화면이 구현되었습니다.

## 기술 스택

- 프론트엔드: 단일 HTML 파일 (인라인 CSS/JS), 별도 설치·서버 불필요
- 백엔드: Google Sheets + Google Apps Script
- 배포: GitHub Pages

## 배포 방법

1. 이 저장소를 GitHub Pages로 배포 (Settings → Pages → main 브랜치 선택)
2. `apps-script/Code.gs` 내용을 Google Apps Script 프로젝트에 붙여넣고 웹앱으로 배포
3. 배포된 Apps Script URL을 `site-config.js`의 `apiUrl`에 입력
4. Apps Script 프로젝트의 Script Properties에 비상 백업용 마스터 비밀번호를 `ADMIN_PASSWORD` 키로 설정합니다. 최초 실행 시 이 값으로 `Admins` 시트에 `ADM-001` 대표님 계정이 자동 생성되며, 이후 관리자는 개별 ID와 비밀번호로 로그인할 수 있습니다.
5. GitHub Pages의 `/admin.html`에 접속해 해당 비밀번호로 로그인
6. SMS OTP를 사용할 경우 Apps Script Script Properties에 `FEATURES_SMS_ENABLED=true`, `TWILIO_SID`, `TWILIO_TOKEN`, `TWILIO_FROM`을 설정
## 고객 접수확인 이메일 트리거 설정

고객 신청 화면의 제출 속도를 유지하기 위해, 접수확인 이메일은 케이스 저장 직후가 아니라 Apps Script 시간 기반 트리거가 별도로 발송합니다. 트리거를 등록하지 않으면 Cases 시트의 `확인메일발송상태`가 `대기`로 남고 메일은 발송되지 않습니다.

1. Google Sheets에 연결된 Apps Script 편집기에서 왼쪽 **트리거** 메뉴를 엽니다.
2. 오른쪽 아래 **트리거 추가**를 선택합니다.
3. 실행할 함수로 `processPendingConfirmationEmails`를 선택합니다.
4. 이벤트 소스는 **시간 기반**, 유형은 **분 단위 타이머**, 간격은 **1분마다**를 선택합니다.
5. 저장 후 권한 요청을 승인합니다.

## 배포 후 연결 테스트 체크리스트

1. `site-config.js`의 `apiUrl`을 실제 배포된 Apps Script 웹앱 URL로 교체합니다.
2. `admin.html`에서 관리자 비밀번호로 로그인해 성공 여부를 확인합니다.
3. 관리자 화면에서 테스트 업체 1개를 등록하고 Google Sheets `Contractors` 시트에 행이 생기는지 확인합니다.
4. `index.html`에서 무료 자격확인을 제출해 `Leads` 시트와 안내 이메일을 확인합니다. 이메일의 `leadId` 링크는 서버 응답 전 기본 폼 대신 로딩 화면을 표시하며, 저장된 서비스 확인·동의·결제를 완료한 뒤에만 `Cases` 시트에 행이 생기는지 확인합니다.
5. 등록한 업체의 계약서 링크로 `contract.html`을 열어 작성하고 선택 서류를 업로드한 뒤, `Contractors` 시트에 라이선스·본드 정보와 Drive 파일 링크가 채워지고 관리자 알림 메일이 오는지 확인합니다. 최초 실행 시 Drive 권한 승인이 필요할 수 있으며, 저장 폴더 ID는 `DRIVE_FOLDER_ID` Script Property에 자동 기록됩니다.

`file://`로 직접 열면 브라우저 CORS 정책으로 호출이 실패할 수 있으므로 GitHub Pages 등 실제 웹서버로 배포한 상태에서 테스트하세요.

## 광고 유입 페이지

소셜 광고(페이스북 등)의 도착 URL은 GitHub Pages의 `/landing.html`을 사용합니다. 랜딩 페이지의 “무료 자격 확인하기” 버튼은 고객 인테이크 화면인 `/index.html`로 연결됩니다.

## 협력업체 지원서 및 검토

협력업체 공개 지원서 URL은 GitHub Pages의 `/contractor-apply.html`입니다. 로그인 없이 지원서를 접수할 수 있으며, 동일 이메일 또는 연락처의 24시간 내 중복 접수는 차단됩니다. 접수 성공 시 지원자에게 접수 확인 메일을, 관리자에게 신규 지원 알림 메일을 각각 발송하며 한쪽 발송 실패가 접수 자체를 취소하지는 않습니다. 운영자는 `/admin.html` 로그인 후 **지원자 검토** 탭에서 상태를 선택해 지원서를 조회하고, 상세 본드·경력 정보를 확인한 뒤 승인 또는 거절할 수 있습니다. 승인하면 업체 계정과 계약서 작성 링크가 자동 생성되어 지원자 이메일로 발송됩니다. 이메일 발송이 실패한 경우에도 승인은 유지되며 화면에 표시된 액세스코드를 직접 전달하면 됩니다.

## 신청 대행 이용료 및 동의

기본 `index.html`에서는 결제 없이 무료 자격확인만 진행하며 차량/충전기/둘 다 품목만 선택하고 가격은 표시하지 않습니다. 서버가 기존 매칭엔진과 프로그램 운영 상태를 적용해 `Leads`에 `가능성있음` 또는 `부적격`으로 기록하고 브랜드 HTML 안내 이메일을 보냅니다. 가능성 이메일에서 추천 품목과 이용료($99/$149/$199)를 처음 공개하며, 구체적인 프로그램명과 예상 지원금은 넣지 않습니다. 가능성 있는 고객은 이메일의 고유 링크로 돌아와 저장된 정보를 다시 입력하지 않고 서비스 유형을 확인한 뒤 동의·결제를 진행합니다. Stripe 결제가 확인된 후에만 기존 Cases 접수가 생성되고 리드는 `전환완료`가 됩니다. 관리자는 **리드 관리** 탭에서 상태별 조회와 7일 이상 미전환 리드의 안내 이메일 재발송을 할 수 있습니다.

충전기 설치·전기패널 업그레이드 공사비가 지원금 한도를 초과하면 차액은 고객이 부담합니다. 관리자 화면의 **케이스 검토**에서 케이스를 검색한 뒤 예상공사비와 예상지원금한도를 입력하면 고객부담예상액이 자동 계산되어 Cases에 저장됩니다. 미입력과 0달러는 구분되며, 지원금이 공사비 이상이면 고객부담액은 0입니다. 관리자는 고객에게 전화/이메일로 견적과 차액을 안내하고 공사 진행 의사를 별도로 확인합니다. 견적 자동 이메일은 후속 작업입니다.

새 견적 저장 기능을 사용하려면 변경된 `apps-script/Code.gs`를 Apps Script에 반영하고 웹앱을 새 버전으로 배포해야 합니다.

신청 대행 이용료는 차량 프로그램만 진행할 때 $99, 충전기·전기패널 업그레이드만 진행할 때 $149, 둘 다 함께 진행할 때 $199(개별 구매 대비 $49 할인)입니다. 충전기·전기패널 업그레이드를 포함한 $149/$199 이용료는 실제 시공 시 시공비에서 전액 차감되며, 차량만 $99는 시공이 없으므로 차감 대상이 아닙니다. 고객은 가능성 확인 이메일 링크로 재진입하면 저장된 추천 서비스와 이용료를 수정 불가능한 정보로 확인하고, 기존 동의서를 끝까지 확인해 전자서명한 후 결제합니다. 다른 서비스를 원하면 기본 자격확인을 처음부터 다시 진행해야 합니다. 신청정보·동의 여부·시각·서명·이용료와 매칭결과는 PendingPayments에 임시 저장되며, Stripe API 검증 또는 관리자 수동 결제 확인 후에만 Cases에 접수됩니다. 브라우저 저장소에는 신청정보를 저장하지 않습니다. 링크 미설정 시 준비 중 안내만 표시하고 임시 저장이나 이동은 하지 않습니다.

## Stripe 결제 설정 및 운영

### 환불 정책 및 관리자 처리

결제일로부터 **3영업일 이내 취소 요청 + 정식 프로그램 신청서 제출 전** 두 조건을 모두 충족하면 전액 환불하며, 그 외에는 환불되지 않습니다. 이 조건은 차량만·충전기만·번들 세 유형에 동일합니다. 충전기·전기패널 공사를 포함한 $149/$199 이용료의 시공비 전액 차감 정책은 유지하고, 차량만 $99는 차감 대상이 아닙니다. 취소 요청은 문의 이메일로 CaseID와 함께 받습니다.

관리자 **케이스 검토**에서 환불 가능 여부 배지와 결제일시를 확인하고, **환불 처리 → 사유 입력 → 환불 처리 확인**으로 기록합니다. 실제 카드 환불은 먼저 Stripe 대시보드에서 처리해야 하며 이 기능은 카드 환불 API를 호출하지 않습니다. 불가 건도 확인창을 거쳐 예외 처리할 수 있고, 사유에 `[예외처리]`가 붙습니다. 완료 건은 일시·사유를 표시하고 버튼을 숨깁니다.

- 자동판별은 영업일 대신 달력일 3일(72시간, 경계 포함)로 근사하며, 허용 상태는 대기·배정됨·방문예정·시공중·서류접수입니다. 제출 이력이 있으면 현재 상태를 되돌려도 불가로 표시합니다.
- 자동 배지는 현재 시각 기준 참고 표시입니다. 고객의 취소 요청일, 주말·공휴일 및 실제 제출 여부를 확인하세요. 허용 목록 밖의 미제출 상태도 관리자 확인 후 예외 처리할 수 있습니다.
- Cases의 `결제일시`는 결제 검증 또는 관리자 결제 확인 후 케이스를 생성한 서버 시각이며 재시도 시 바뀌지 않습니다. 실제 Stripe 결제일과 다를 수 있으므로 지연 접수 건은 대시보드와 대조하세요. 기존 케이스는 날짜를 임의 소급하지 않으며 미기록 시 자동판별 불가입니다.
- `환불처리여부/환불처리일시/환불사유`와 StatusHistory의 환불처리 이벤트를 함께 기록합니다. 기존 업무 상태는 유지하고 중복 요청은 중복 이력을 만들지 않습니다. 부분 저장 실패 후 재시도하면 최초 이력으로 복구합니다.
- 변경된 Code.gs를 새 버전으로 배포해야 새 컬럼과 API가 적용됩니다. 실제 환불·배포 화면 테스트는 아직 하지 않았습니다.
- 법적 효력은 별도 변호사 검토가 필요합니다. 특히 캘리포니아 Home Solicitation Sale 관련 법규와 Civil Code 1689.5 검토 TODO를 유지합니다.

### Stripe 최초 설정

웹훅이나 새 중계 서버는 사용하지 않습니다. Apps Script가 Stripe API로 결제 세션을 직접 조회합니다. 테스트 Payment Link 3개가 `SITE_CONFIG.stripe.test`에 연결되어 있고 `testMode: true`인 동안 이 링크를 사용합니다. 운영 전에는 운영 링크와 비밀키를 설정하고 테스트 모드를 해제해야 합니다.

1. Stripe 계정을 만들고 **일회성 USD $99 / $149 / $199 Payment Link**를 각각 생성합니다. 수량은 1로 고정하고 할인·자동 세금·통화 변환은 사용하지 않습니다. 서버는 정확한 금액을 대조합니다.
2. 세 링크의 결제 후 이동 URL을 모두 다음으로 설정합니다: `https://tubasa22.github.io/ev-incentive-app/payment-success.html?session_id={CHECKOUT_SESSION_ID}`.
3. 생성된 운영 링크를 `site-config.js`의 `SITE_CONFIG.stripe.live.paymentLinkVehicleOnly`, `paymentLinkChargerOnly`, `paymentLinkBundle`에 각각 입력합니다. 테스트 중에는 `SITE_CONFIG.stripe.test`의 테스트 링크와 `testMode: true`를 사용하며, 운영 전환 시 운영 비밀키와 함께 `testMode: false`로 바꿉니다. 현재는 기본 `https://buy.stripe.com/…` 링크를 지원합니다.
4. Stripe 대시보드의 **Secret key**를 Apps Script Script Properties의 `STRIPE_SECRET_KEY`에 저장합니다. **Publishable key가 아닙니다.** 비밀키는 HTML·site-config.js·Git 저장소에 넣지 않습니다.
5. 변경된 `apps-script/Code.gs`를 편집기에 반영하고 웹앱을 **새 버전으로 배포**합니다. PendingPayments 시트와 감사용 추가 컬럼은 첫 사용 시 자동 생성됩니다.
6. 기존 `processPendingConfirmationEmails` 1분 주기 트리거와 메일·외부 요청 권한을 확인합니다. 결제 확인은 메일을 직접 보내지 않고 기존 발송 대기 처리에 연결합니다.
7. 먼저 별도 테스트 시트·테스트 Payment Link·테스트 비밀키로 아래 시나리오를 확인합니다. 운영 전에는 운영용 링크 3개와 운영 Secret key를 함께 설정합니다. 웹훅 등록과 웹훅 시크릿은 필요 없습니다.

### 신청 토큰 전달 방식

결제 링크에 `client_reference_id=PAY-…`를 코드가 자동으로 붙입니다. Stripe가 공식 지원하는 성공 URL 치환값은 `{CHECKOUT_SESSION_ID}`이므로, 임의의 `{토큰}`을 성공 URL에 넣지 않습니다. 성공 페이지가 세션ID를 보내면 서버가 Stripe API로 해당 세션을 조회하여 `client_reference_id`에서 신청 토큰을 복원합니다. URL에 `token`을 별도로 전달한 경우에는 서버가 일치 여부도 검증합니다. 브라우저 저장소나 UTM 파라미터에 토큰을 저장할 필요가 없습니다.

근거: [Stripe 결제 후 이동 설정](https://docs.stripe.com/payment-links/post-payment), [신청 토큰 연결 파라미터](https://docs.stripe.com/payment-links/url-parameters), [결제 세션 조회 API](https://docs.stripe.com/api/checkout/sessions/retrieve).

### 미확인 결제와 장애 복구

- 성공 페이지는 최대 20초 동안 3초 간격으로 결제를 확인합니다. 미결제·네트워크 실패·미설정 시 재시도 또는 관리자 문의를 안내합니다. 고객이 결제 후 페이지로 돌아오지 않으면 자동 확인도 실행되지 않습니다.
- 관리자 **정산 관리 → 결제 미확인 건**에서 24시간 이상 대기 건을 조회합니다. Stripe 대시보드에서 결제 완료, 신청 토큰, USD 금액을 직접 대조한 뒤 해당 `cs_live_…`(테스트는 `cs_test_…`) 세션ID를 입력하고 **결제 확인됨(수동)**을 누릅니다. 이 기능은 관리자 판단에 따라 접수하므로 미결제 건에는 누르지 않습니다.
- 완료 요청 재전송은 중복 케이스를 만들지 않습니다. 케이스 저장 후 이력·완료 상태 기록만 실패한 경우에도 토큰을 통해 기존 케이스를 찾아 복구합니다. 같은 세션을 다른 신청에 재사용할 수 없습니다.
- 확인메일은 기존 트리거가 발송합니다. 접수 완료 화면은 메일이 이미 발송됐다고 표시하지 않습니다. 메일 실패는 Cases의 확인메일발송상태로 별도 점검합니다.
- PendingPayments에는 생성일시·가격유형·금액·상태·세션ID·임시 신청/매칭 JSON·최종수정일시와 접수CaseID·확인방식·관리자ID/이름·확인일시를 보관합니다. 개인정보 접근권한과 미결제 정보의 보관·삭제 기한은 운영 전에 정해야 합니다.

- 실제 배포 후: $99/$149/$199 정상 결제, 결제 취소/미완료, 잘못된 토큰·금액, 성공 페이지 새로고침, 브라우저 종료 후 수동 확인, 확인메일 트리거 발송을 테스트합니다.

## SMS 기능 켜는 방법

기본값은 SMS 비활성입니다. Google Sheets에 연결된 Apps Script의 Script Properties에 `FEATURES_SMS_ENABLED`를 `true`로 추가하고, `TWILIO_SID`, `TWILIO_TOKEN`, `TWILIO_FROM`에 실제 Twilio 값을 설정하면 코드 변경 없이 SMS OTP 발송이 활성화됩니다. 해당 속성이 없거나 `false`이면 계약서 화면에서 등록된 이메일로 인증번호를 받거나, 관리자 수동 전화 확인을 선택할 수 있습니다. 이메일이 없는 직접 등록 업체는 전화 확인 경로만 사용할 수 있습니다.

## 제휴 딜러 소개 및 소개비 관리

관리자는 **딜러 제휴** 탭에서 딜러명·담당자·연락처·참여프로그램·예상 소개비와 활성 상태를 관리합니다. MyFirstEV가 관리자 매칭 결과에 포함된 케이스만 활성 딜러에게 소개할 수 있으며, 소개 시점과 담당 관리자 이력이 기록됩니다. 클린EV는 고객을 소개할 뿐 차량 가격 협상이나 거래 조건에는 관여하지 않습니다.

**정산 관리 → 딜러 소개비 관리**에는 소개 완료 후 아직 소개비를 받지 않은 케이스만 표시됩니다. 수령 금액과 날짜는 Cases에 기록되며 하청비 지급 및 정부 정산 수령과는 독립적으로 추적됩니다. 이 정보는 관리자 전용이며 고객·컨트랙터 화면에는 노출되지 않습니다. 변경된 `Code.gs`를 Apps Script에 반영해 새 버전으로 배포해야 `Dealers` 시트와 Cases 추가 컬럼이 자동 생성됩니다.

## 프로그램 신청 중단·재개

클린EV의 주 서비스 지역은 LA·오렌지카운티·사우스베이의 South Coast AQMD 관할입니다. 차량 프로그램은 RYR·CC4A·MyFirstEV를 주력으로 안내하고, South Coast AQMD 밖이거나 관할을 확정하기 어려운 경우에만 DCAP을 대체 후보로 후순위 표시합니다. 충전기 지원은 이 지역의 주요 전력회사인 SCE·LADWP 유틸리티 리베이트를 우선 안내하며, 개인 주택 해당성이 낮은 CALeVIP은 항상 마지막에 표시합니다.

이 우선순위 조정은 결과 배열의 포함 범위와 표시 순서만 다루며 FPL 계산, CC4A 공식 금액, 딜러 소개 및 3단계 가격 로직은 변경하지 않습니다.

### 신청 검증과 관리자 매칭 결과

이름·전화·이메일·ZIP·주택소유, 가구원수·소득·신고연도, 서비스 유형·기존 EV 보유·과거 신청여부는 필수입니다. 서비스는 첫 단계에서 차량만($99)/충전기만($149)/번들($199, $49 할인) 라디오로 선택합니다. 충전기 전용이면 기존차량 단계 전체를 숨기고 필수 입력을 해제하며 앞뒤 이동에서도 건너뜁니다. 차량만/번들로 바꾸면 차량 연식·연료·본인명의와 희망 구매유형을 다시 요구합니다. 희망 차종은 PHEV/ZEV/전기오토바이/전기자전거 중 선택할 수 있는 선택 항목이며, 미선택 시 CC4A/DCAP는 ZEV 일반 지역 금액으로 추정합니다. 과거 신청이 없으면 '없음'을 선택합니다. 전기패널 용량은 아는 경우만 입력합니다. 단계별 인라인 오류와 최종 전체 검증을 통과해야 결제 준비를 진행하며 서버도 필수값을 다시 검사합니다.

매칭결과JSON은 `vehiclePrograms` / `chargerPrograms` / `mutuallyExclusiveWarning`과 기존 계산 문맥(`context`)을 저장합니다. 각 프로그램은 기존 `id/name/amount/reason/isActive/docs` 필드를 유지합니다. 각 그룹은 예상금액 내림차순이며 RYR/CC4A/DCAP 중 둘 이상이 해당하면 '이 중 하나만 신청 가능합니다' 경고를 표시합니다. 번들이면 두 그룹을 계산하고 CALeVIP에는 개인고객 적용 주의를 표시합니다. 충전기 전용은 차량 판정을 건너뛰고 유틸리티 리베이트만 계산하며, 관리자에는 "차량 프로그램: 해당없음(신청 안 함)"을 표시합니다. 서버도 기존 판정식을 실행하여 클라이언트가 보낸 결과 대신 재계산한 값을 저장합니다. 브라우저와 서버의 프로그램 기준 설정은 테스트로 동기화를 확인합니다.

CC4A/DCAP는 2024-25 Funding Plan 기준으로 FPL 300% 이하를 판정하고 희망 차종별 일반 지역 지원액을 계산합니다. 폐차 대상 차량이 없으면 제외하지 않고 DCAP 금융지원 대안을 `조건부 가능`으로 남깁니다. DAC 여부와 관할 air district는 자동 확정하지 않으며, 관리자 화면에서 CalEnviroScreen·관할 지역·평생 1회·구매 차량 연식 조건을 수동 확인하도록 안내합니다. 충전 희망 시 CC4A 내부의 충전기 또는 선불충전카드 최대 $2,000을 별도 유틸리티 리베이트와 구분해 표시합니다.

고객에게는 매칭 결과를 표시하지 않습니다. 관리자 케이스 검토에서만 그룹별 순위·비활성 배지·상호배타 경고를 확인합니다. 구형 `results` 저장 데이터도 읽을 수 있습니다. 서버가 재계산한 새 형식은 PendingPayments를 거쳐 결제 확인 후 Cases에 그대로 저장됩니다. **Code.gs 새 버전 배포가 필요합니다.**

로컬 검증: `node tests/matching.test.cjs`, `node tests/payment-flow.test.cjs`, `node tests/payment-pages.test.cjs`, `node tests/pricing-copy.test.cjs`. 실제 브라우저·Sheets 배포 검증은 별도로 진행해야 합니다.

### 프로그램 운영 토글

`/admin.html`에 로그인한 뒤 **프로그램 관리** 탭에서 RYR, CC4A, DCAP, MyFirstEV, CALeVIP, 유틸리티리베이트, SCAQMD 충전기 리베이트의 토글·메모·다음 확인 예정일을 저장합니다. 예정일이 지나면 **확인 필요** 배지가 표시되며 SCAQMD 항목은 운영 확인 전 기본 비활성입니다. 비활성 프로그램은 새 고객 케이스의 관리자용 매칭 결과에 **현재 신청 일시중단**으로 남습니다.

매칭엔진에는 SCE Charge Ready Home, SCE/LADWP 중고 EV 리베이트, LADWP 충전기 추가지원과 South Coast AQMD 주거용 충전 리베이트 기준이 구조화되어 있습니다. DAC는 자동 조회하지 않으며 관리자 케이스 상세에서 SB 535 지도를 열고 주소/ZIP을 복사한 뒤 `DAC 해당`·`DAC 미해당`·`미확인`으로 저장합니다. DCAP Financing Assistance는 2026-08-21 기준 신규 신청 중단 안내를 표시합니다.

LADWP 관할의 충전기·번들 신청에는 리베이트를 사업체가 직접 수령하도록 제3자 지급대상을 지정할 수 있다는 안내가 표시됩니다. 관리자 케이스 상세에서는 해당 옵션의 안내 완료 여부를 체크해 Cases의 `LADWP제3자지정안내여부`에 기록합니다.

LADWP 관할 충전기 케이스를 배정받은 컨트랙터에게는 포털에서 8단계 설치 행정절차 체크리스트를 제공합니다. 절차 진행도는 Cases의 `LADWP절차단계`에 저장되며 기존 케이스 상태와 독립적으로 운영됩니다. 4단계 온라인 신청은 6단계 전기허가·시공 전에 완료해야 하고, 다세대주택에는 전기 설계도면으로 일정이 늘어날 수 있다는 참고가 표시됩니다.
